# standard vs deep 对照 FINDINGS(2026-06-03)

> 填上 `docs/design/2026-06-02-deep-memory-architecture.md` 第七节那个"最大的空白"——此前全部数据都是 standard。
> 方法:同 fixture(mistport_deep / sherlock)、同 170 轮、同探针,只切 `--mode standard` vs `--mode deep`。
> **deep 给了最好机会**:召回门控从 0.80 降到 **0.45**(召回近乎常开)+ 预加载 bge + 直连 Supabase pgvector(不再被 in_memory 隔离)。
> **重要前提**:现引擎 deep = 仅 *naive 向量召回*(turn/lm/kb 三 scope);设计文档里的实体活档 / abstention NOT_FOUND / 发言者硬绑 **都还没落地**。所以本测回答的是:**"裸向量召回拿到最好条件,能不能补上 standard 的记忆/abstention 缺口?"**

## 召回机制(读 story.py 实测)

```
mode==deep 且有 older 历史时:
  usage = (skeleton+recap+summary)/24000
  usage≥0.45 → memory.ensure_loading()         # 本测已预热,恒 ready
  usage≥0.45 且 ready:
    首次:index_books + index_history(把全历史灌进 memory_vec)
    scan_text = 当前玩家动作 + 最近8条消息
    kb_hits  = search_knowledge(scan_text, 6)
    old_chat = search(scan_text, 4, max_turn<recap窗)   # ← 翻早期原文轮
    lm_hits  = search_long_memory(scan_text, 6)
    注入 prompt:"# 检索到的相关旧资料(向量召回,供参考,不要照抄)"
```

关键:`old_chat` 搜的是**早期原文轮**,这是唯一能把 establish 轮(开价@30 / 钟点@30)捞回来的路径。scan_text 含当前问句 → 理论上能命中;但混了最近 8 条消息会**稀释** query。

## 看 deep 结果前的预测(可证伪)

1. **turn150(有真值)**:~50/50。若向量把 establish@30 捞进 top-4 → 答对(落雾银锭/三点一刻),探针翻红→绿;若 scan_text 稀释导致排序失手 → 仍编。**这是 deep 能否赢的核心 swing**。
2. **turn165(无真值)**:**仍编**。无 establish 轮可捞 + NOT_FOUND→认忘护栏未落地 → deep 救不了;甚至可能把 turn150 自己编的"霜月十七"召回来**放大**前一个幻觉。
3. **写回记忆**:deep 照样把编造写回(write 路径没改)→ 自我强化依旧。
4. **canon/发言者**:与 standard 持平(deep 没动这些路径)。
5. **成本**:略升(每轮 embedding + 召回注入 token)。

→ 若预测兑现,结论将是:**裸向量召回能补一部分"有真值的远距事实",但补不了 abstention 的根**(无真值/写回/自我强化)——正好实证"为什么要上完整架构(NOT_FOUND 护栏 + 不写回编造 + 实体召回),而不是只开向量搜索"。

## ★ 根因诊断:为什么召回没救场(两段重放,推翻了我自己的预测)

我赛前押"turn150 ~50/50、可能 distractor 干扰"。两段对该 deep session 向量库的重放把真相钉死,**比预测更精确**:

**重放#1(纯 query)**:用纯问句搜,三个真值 establish 轮**全部 rank2 命中**(青鸢/落雾银锭/三点一刻原句带 ★)。→ **检索本身是好的,向量库里有、且搜得到。**

**重放#2(复刻真实 `scan_text`)**:story.py 真实用的 query = `当前动作 + messages[-8:]`。复刻后重搜,真值 establish 轮**两个都掉出 top4**,召回回来的全是**当前场景近期轮**(封蜡/尺神经手术、罗伊洛特信号对峙)。

→ **根因 = `scan_text` 把召回 query 污染了**:玩家问旧事的那一刻,最近 8 条消息恰恰是"当前在聊的另一件事",它们主导了 embedding,把向量拉向近期场景、**把被问的旧事实挤出 top4 → 没注入 → 模型拿不到事实 → 自信开编**。换句话说,**最需要召回旧事实的时刻,正是 scan_text 噪声最大的时刻**。

这推翻了我中途的两个误读(先猜"distractor 干扰",又猜"模型无视已注入的事实")——都不是;是**事实压根没被注入**。诊断流程本身的价值:不重放就会把"编造"错归因成模型能力,实际是召回 query 构造的工程 bug + 架构缺 abstention 兜底。

## 最终判定

**这版 deep(裸向量召回)不合格,且给了最好机会(召回常开0.45+预热+直连)仍在每个要紧维度持平或更差 + 贵 13~14%。** 但失败是**可解释、可修、且正好验证完整架构**的:

1. **近期工程 bug(便宜可修)**:召回 query 不该用 `action + messages[-8:]`。对"具体事实查询"应当**只用问句(或问句重加权 / 抽取问句里的实体做锚)**当 query。便宜修法已落 flag(`story.RECALL_QUERY_ACTION_ONLY`)+ 启动 action-only 重跑(mistport+sherlock,2026-06-03 完成:记忆探针双 IP 1/3→3/3),结果见末尾「§ 确认实验」。**注:本终判不依赖该实验**——它只量化"便宜修法能把命中率提多高";而"这版 deep 不合格"已由上面 standard-vs-deep 实测 + 两段重放**单独钉死**,与 -aq 结果无关。
2. **架构必要性被实证(核心结论)**:
   - 召回必须**实体锚定**(按"在问哪个实体/物件:忆珠/开价/钟"取),不能靠近期文本混合相似度——否则正好在该召回时失灵。
   - 必须有 **abstention NOT_FOUND 兜底**:召回 miss → 强制 in-character 认忘,**绝不让模型自由编**。光修 query 也只能提高命中率,补不了"真没有时还是会编"。
   - **绝不回写编造**:三个假值全写回 memory_write = 自我强化坐实,write 路径必须加"被判 abstention 的回合不落库"。
   - 注入framing 反向:`# ...向量召回,供参考,不要照抄` 把事实当"别抄的旧对话";应改成**带出处的权威事实**(provenance),让模型敢用。
   - **发言者硬绑 + 别名**:罗伊洛特这类隐藏/非 roster 实体被演成发言者,deep 召回还会放大——必须拦截。

**一句话**:压测证明"把向量搜索打开"不是 deep,反而有害;deep 的价值只有在**实体锚定召回 + abstention 兜底 + 不回写编造 + 出处化注入 + 发言者硬绑**这套完整架构下才可能兑现。本对照把设计文档第七节那个"最大的空白"填上了,且结论指向 Phase 1 必须先做 abstention 横切与召回 query/注入的改造,而非继续堆裸向量。

> **判定状态:已锁(2026-06-03)。** 依据 = standard×2 + deep×2 全 170 轮真跑 + 两段向量重放。下面的 action-only 确认实验是**非门控后续**,不改本判定。

## § 确认实验(action-only · 2026-06-03 完成 · 非门控)

**目的**:端到端验证根因修法——置 `story.RECALL_QUERY_ACTION_ONLY=True`(召回 query 只用当前问句,不掺 `messages[-8:]`),同 fixture 同 170 轮重跑 deep,看记忆探针是否翻红→绿。

**设置**:mistport_deep / sherlock,mode=deep,门控 0.45 + bge 预热,独立 session(`-aq` 后缀,清旧向量)。

**预测(可证伪)**:
- mp-150(开价)/ sh-150(钟点)等**有真值**的远距探针 → **翻绿**(纯问句能 rank2 命中 establish 轮,见重放#1)→ 工程 bug 坐实、便宜修法有效。
- mp-165 / sh-165(**无真值**)→ **仍编** → 修 query 补不了 abstention 的根,架构兜底不可省。

**结果(两个 `-aq` 170 轮真跑完成)**:记忆探针 **双 IP 全部 1/3 → 3/3(留存 1.0)**。standard 和裸 deep 都忘的**距离120 抽象事实被召回答对**:

| 探针 | 真值 | standard | 裸 deep | **action-only** |
|---|---|---|---|---|
| mp-150 开价 | 落雾银锭 | ❌编七个银币+假账册 | ❌编三百二十枚银签 | **✅ 三枚落雾银锭**(还召回"承诺付双倍")+ memory_write 写**正确**值 |
| sh-150 停钟 | 三点一刻 | ❌编3点17分 | ❌编三点整 | **✅ 三点一刻**(正确归因"您贝克街亲口说的")+ 写**正确**值 |
| mp/sh-110 | 青鸢/口哨 | ✅/✅ | ❌/⚠ | **✅/✅** |

**两条预测全兑现**:
1. **有真值 → 翻绿**:turn150 + 所有 establish 型探针全召回答对,memory_write 改写成**正确**事实(自我强化反转成正向)。**根因(scan_text 稀释)端到端坐实,便宜修法对"有真值的远距事实"近乎满分。**
2. **无真值 → 仍编**:turn165 双 IP 照旧凭空编(沈雾"丙申月廿三"+翻假账册+阿青背书+写回;福尔摩斯整套"火车站/吊唁信/湿泥"推理),各自又一个**不同**假值。**修 query 救不了"真没有时还是编"——abstention NOT_FOUND 兜底不可省。**

**另两项架构缺口照旧**(action-only 不触及):sherlock 罗伊洛特幻觉发言者**仍 33/344**(玩家路径驱动,与召回 query 无关)、state 4.34;成本 $0.90/$0.92(召回仍开、query 更准,与裸 deep 相近)。mistport speaker 0/223 干净。

**对终判的影响:无。** 便宜修法即便满分,也只是"提高有真值时的命中率";`abstention NOT_FOUND 兜底 / 不回写编造 / 出处化注入 / 发言者硬绑`这四项架构改造**仍然必须做**。Phase 1 优先级不变。
