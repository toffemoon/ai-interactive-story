# 设定卡 母版（总纲）

> 这是母版 / 总纲，不逐个设定填写。它定义所有「设定卡」共享的字段、frontmatter、知识分层和接引擎方式。具体填写时从它派生子类（现成两个：组织、地点），从对应子类模板取正文骨架。

---

## 1. 设定的四层与设定卡的位置

「设定」不是一种东西，是四层。设定卡是中层，本母版只管中层；上下两层是它的来源 / 邻居。

| 层 | 是什么 | type | 本母版管 |
|---|---|---|---|
| 顶层·世界母本 | 一个世界一份的圣经（世界观 / 历史 / 知识分层 / 主题） | 设定集 | 否（设定卡用 `母本` 指回它，不重复世界级背景） |
| 中层·设定卡 | 单个组织 / 地点 / …… 的完整中层设定 | 设定卡 | 是 |
| 底层·世界书条目 | 关键词触发的碎片条目，直接喂引擎 | 世界书 | 否（独立的一类，见 §5） |

口径一：设定卡 = 引擎一类独立的分析类型。它是中层完整设定，引擎应单独解析整张设定卡（像角色卡 / 故事书那样自成一类），不是只「切碎成世界书条目」。和世界书的分工：设定卡 = 完整中层设定（组织 / 地点 / … 的全貌）；世界书 = 底层碎片化关键词条目——两类不同的引擎处理，世界观完整度也不一样。把设定卡切成世界书条目（§5）是可选的附加注入手段（碎片召回省 token），不是设定卡的主身份，更不是唯一去向。

口径二：子类不限组织 / 地点。现成两个子类是组织 / 地点（城邦 / 村庄 / 区域 / 设施 / 秘境都归地点），但设定卡这一类可按需扩子类（如阵营 / 势力 / 物品体系 / 历法等），不被组织 / 地点框死。

---

## 2. 统一 frontmatter

各子类设定卡都用这套。`<...>` 为占位，填完删尖括号；用不到的行直接删，不要留空字段。

```yaml
---
created: <YYYY-MM-DD HH:MM>
updated: <YYYY-MM-DD HH:MM>
type: 设定卡
tags: [AI互动故事, <世界/IP简称>, 设定卡, <子类，如 组织 | 地点>]
ip: <所属 IP / 世界；原创世界写世界名>
类别: <子类，如 组织 | 地点>
场景类型: <地点专用：城邦 | 村庄 | 区域 | 设施 | 秘境；非地点删此行>
母本: "<世界> 设定集"             # 依附的顶层世界母本；无母本的独立世界设定删此行
档位: <轻量 | 满配>              # 默认轻量，见 §3
召回关键词: [<专名1>, <专名2>, <地点>, <组织>]  # 接世界书切条 + 向量召回
作者: 太妃月 / Toffeemoon
---
```

字段说明（每行填什么）：
- `type`：固定 `设定卡`。
- `类别`：本卡是哪个子类。子类可扩，不限组织 / 地点。
- `场景类型`：仅地点子类用，区分聚落 / 设施等形态；非地点删。
- `母本`：指回所属顶层世界母本，不在卡里重复世界级背景。
- `档位`：轻量或满配，默认轻量。
- `召回关键词`：本卡的标志性专名，供引擎切条与向量召回命中。

## 3. 两档充实度：默认轻量

设定卡默认走轻量档；只有反复出场、剧情承重的核心组织 / 核心地点才升满配。

| | 轻量档（默认） | 满配档 |
|---|---|---|
| 适用 | 大多数设定；引擎条目化吃这个 | 反复出场、剧情承重的核心组织 / 地点 |
| 体量 | 概览 + 几个结构化段 + 召回关键词 + 剧情钩子 | 十几节全展开（起源 / 各部门 / 核心逻辑 / 场景设计 / 开场白库） |
| 正文 | 见各子类模板的「轻量正文」 | 轻量正文 + 子类模板列出的「满配可展开」清单 |

升档随需：一个轻量设定被玩家反复牵动、变成剧情主场，再补满配段。不要一上来就满配。

## 4. 共享字段骨架：引擎摘要块

各子类设定卡顶部都放一个「引擎摘要」块（和角色卡母版同构）。给引擎快速解析，人也能一眼读懂这个设定。四个固定字段：

### 4.1 一句话锚点（anchor）
一句话说清「这是什么、对玩家 / 剧情是什么、底色是什么」。抽象示例：「某个披着 X 外衣、实际靠 Y 运转的势力，最危险处在于它显得无害」。

### 4.2 召回关键词（keys）
玩家近期消息 / 当前所在地命中这些词 → 引擎注入这张卡（或相关段）。给标志性专名、地名、组织名，不要给泛词。直接对接 §5 的世界书切条。

### 4.3 知识分层 / 可见性
这套设定里哪些角色可知（`public`）、哪些是元真相默认不注入（`hidden`）。沿用顶层母本的 L1–L4 体系：

| 记号 | 含义 |
|---|---|
| public（L1–L2） | 角色可知、可注入、可由 NPC 说出 |
| hidden（L3–L4） | 元真相 / 反转，普通角色不知；设定照常注入给 AI（AI 全知），但 AI 默认不说出 / 不暗示，解锁条件满足才由叙事引入。玩家界面不展示 |

设定卡里凡涉及 hidden 的内容，就近标注门控（见各子类「剧情钩子」字段的写法）。机制上，hidden ≠「不注入」：设定照常注入给 AI（AI 全知），hidden = AI 知道但默认不说出 / 不暗示，解锁条件满足才由叙事引入；门控控的是「说不说」，不是「注不注入」。防剧透靠 AI 输出克制（hard_violation / 披露控制）+ 玩家界面不展示，不靠「不注入」。另：设定里不可违背的铁律 / 法则（非「会变的状态」）切成世界书条目时标 `硬canon: 是`，对接引擎已落地的 hard_violation（违背即世界内反制）。

### 4.4 口吻 / 禁区
这套设定相关的 NPC / 场景说话调性 + 不能写成什么。抽象示例：「冷峻克制、信息密度高；不要写成轻松日常或纯正派据点」。

### 4.5 可选段（按需补，没有就删）
以下段不是每张卡必填，能让设定立体就加，填什么写一句：

| 段 | 填什么 |
|---|---|
| 运作机制 | 这个设定靠什么日常运转 / 维系（资源、规则、流程、权力链条） |
| 玩家接口 | 玩家能从哪里切入、能做什么、会撞上什么（入口、任务面、可交互点） |
| 实力底牌 | 关键能力 / 资源 / 杀手锏，及其代价或触发条件 |
| 标志物 / 暗语 / 仪式 | 可被识别的符号、口令、仪轨——给场景与对白挂钩 |
| 内部裂痕 / 路线之争 | 内部分歧、派系、矛盾路线——给剧情张力与可玩冲突 |

## 5. 接引擎：设定卡作为独立类型 + 可选切世界书条目

设定卡是给人读 + 给引擎理解的中层完整设定；引擎应把它当独立的一类整张解析（对接「设定卡引擎」，见 §1）。
另：可选把设定卡切成世界书条目作附加的碎片化注入（省 token、按关键词 / 所在地召回）——这是补充手段，不是设定卡的全部。切条规范如下。

每条目四字段：

| 字段 | 填什么 |
|---|---|
| 关键词（keys） | 触发词，逗号分隔，可多个。命中即注入 |
| 来源 | `world` 通用世界 / `rule` 规则 / `location` 按所在地召回 / `figure` 人物 / `org` 组织 |
| 可见性 | `public` / `hidden`（见 §4.3） |
| 内容 | 必须独立完整（standalone）——只有内容注入，标题和关键词不注入；一条要能脱离上下文被读懂 |

两条铁则：
- standalone：每条内容自足。不要写「如上所述」「见前文」。
- 常驻 vs 触发：世界铁则（物理法则、世界基调）可设常驻（constant / always-active）每轮都注入；具体设定靠关键词触发，省 token。配太宽 = 塞爆 context，配太窄 = 该出场不触发。

一张设定卡通常切成：1 条总览（org / location）+ 数条分项（各部门 / 各区域）+ 关键人物指向对应 figure 条。

---

## 6. 与顶层世界母本的关系

设定卡不重复世界级背景。世界观、历史、知识分层主真相写在顶层世界母本（一个世界一份），设定卡用 frontmatter `母本` 指回，只写「这个组织 / 地点自己的事」。顶层母本本身不在本批模板内（一个世界一份、非高频产物）；要新建一个世界时，以现有世界设定集为范本。

---

## 7. 命名与存放

- 组织 / 地点：`<名称> 设定卡.md`，放对应世界目录。
- 地点（含城邦）：`<地点名>.md` 或 `<城邦名> <别称>.md`，聚落放世界的 `城邦/` 子目录。
- 世界书条目：汇总进该世界的 `<世界> 世界书.md`，不一卡一文件。
- 本 `template/` 目录只放空模板。
