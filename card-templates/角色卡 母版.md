# 角色卡 母版（总纲）

> 母版 / 总纲,定义所有「角色卡」共享的字段与分档标准,**不填具体角色**。逐角色填写时从这里派生两档:主要NPC 与 次要NPC。

---

## 1. 卡片家族与定位

「角色卡」是一切由 AI 扮演角色的统称。它与项目其它卡的关系:

| 卡 | 谁来演 | 充实度 | 本母版是否管 |
|---|---|---|---|
| 玩家卡 | 用户(主角视角) | 轻,结构化字段 | 否 |
| 角色卡 · 主要NPC | AI | 两档:轻量(默认)/ 满配 | 是 |
| 角色卡 · 次要NPC | AI | 轻量(单块 / 名册) | 是 |
| 设定卡 | —(组织 / 地点设定) | 长 | 否 |

有反转 / 隐藏真相的角色,不再单列导演隐藏卡:真相写进本卡「知识边界(hidden)」段 + 版本人格,披露节奏挂故事书。

判断一个角色用哪档,看 §4 分档标准。

---

## 2. 统一 frontmatter

主要 / 次要 NPC 卡都用这套 frontmatter。必填项见注释,用不到的行直接删,不留空字段。

```yaml
---
created: <YYYY-MM-DD HH:MM>          # 必填
updated: <YYYY-MM-DD HH:MM>          # 必填
type: 角色卡
tags: [AI互动故事, <世界/IP简称>, 角色卡, <角色名>]
ip: <所属 IP / 世界;原创世界写世界名>   # 必填
类别: <主要NPC | 次要NPC>            # 必填,本卡档位
可玩: <是 | 否>                      # 必填,是否同时有配套玩家卡
配套玩家卡: "[[<角色名> 玩家卡]]"     # 可选,仅「可玩: 是」时填,否则删
密级: <L0 公开 | L2 限 | L4 禁上传>   # 必填,公开卡默认 L0
召回关键词: [<词1>, <词2>, ...]       # 必填,世界书关键词注入 + 向量召回
作者: 太妃月 / Toffeemoon
---
```

`<...>` 为占位,填完删尖括号。

## 3. 共享字段骨架:引擎摘要块（轻量档）

主要、次要 NPC 卡顶部都放一个「引擎摘要」块,给引擎快速解析,人也能一眼读懂。主要 NPC 之后再接散文段(§3.6+),次要 NPC 到摘要块为止。

轻量档固定包含:引擎摘要(锚点 / 核心矛盾 / speech_rules / 召回关键词 / 外貌锚点)+ 身份 + 性格 + 外貌 + 伴生 + 开场白 + 知识边界(public / hidden)。

### 3.1 一句话锚点（anchor）— 必填
一句话说清角色是谁、对玩家是什么、底色是什么。抽象例:「把毕生执念当唯一标尺、把外人当干扰项的孤高匠人」。

### 3.2 核心矛盾（tension）— 主要必填 / 次要可省
角色身上不要被抹平的内在张力(矛盾是人格核心,不是 bug)。抽象例:「执行冷酷规则的清算者,却保留一条私人底线」。

### 3.3 量化 speech_rules — 必填
把说话方式 formalize 成引擎能直接抽的规则,而非埋在散文里。固定子项:

| 子项 | 填什么 |
|---|---|
| 自称 | 默认怎么称自己;何时改口 |
| 称呼玩家 | 怎么叫玩家,禁用哪些 |
| 句长节奏 | 一般几句、信息密度 |
| 高频句式 | 2-4 种标志句式 |
| 口头禅 | 标志词与短语 |
| 禁用 | 绝不出现的语气 / 词 |

### 3.4 召回关键词（keys）— 必填
玩家近期消息出现这些词 → 引擎注入本卡(或相关段)。对齐世界书 World Info 触发 + 向量召回,可比 frontmatter 更细。填标志性专有名词,不要填泛词。

### 3.5 外貌锚点（look）— 主要必填 / 次要一句外形
一句话视觉印象 + 标志特征,供 AI 描写与图像生成。主要 NPC 在散文段展开完整外貌;次要 NPC 摘要块里一句外形即可。

### 3.6 身份（description）— 必填
角色是谁:身份、来历、当前处境一段。

### 3.7 性格（personality）— 必填
核心性格、行为倾向、价值取向一段。

### 3.8 伴生 / 绑定实体 — 可选
角色绑定的分身 / 忆灵 / 搭档 / 宠物(随角色出场、是角色一部分,不单独建卡)。无则删。

### 3.9 开场白（first_mes）— 必填
角色登场时的第一段台词 / 场景,定调 voice 与情境。

### 3.10 知识边界 — 必填
- **public**:角色公开可知、可主动说的范围。
- **hidden**:角色暂不该说破的真相 / 反转 / 别处发生的事。**注意:hidden ≠ 不注入** —— 内容照常注入给 AI(AI 全知、作者可见),「隐藏」落在输出层:玩家界面不可见 + AI 输出克制(不到披露节奏不说破真相、隐藏角色不提前登场)。防剧透靠 hard_violation + 披露节奏 + CoT 自检,不靠不注入(AI 不知道真相就演不出伏笔)。有反转的角色把真相写在这里。

## 4. 分档标准:主要 NPC vs 次要 NPC

| 维度 | 主要 NPC | 次要 NPC |
|---|---|---|
| 角色 | 有名有姓、反复出场、有完整人格与关系网 | 路人 / 功能位(商贩、守卫、村民) |
| 文件 | 一角色一文件 | 一文件一个,或一文件一份名册 |
| 摘要块 | 五项全填(含外貌锚点) | 锚点 + speech_rules + 一句外形必填,矛盾可省 |
| 正文 | 两档:轻量 / 满配(满配段见 §5) | 无,只摘要块 + 知识边界 + 一句外形 |
| 知识边界 | 必填(可分写进人际 / 当前情境) | 必填独立字段(次要 NPC 最易乱说主线) |
| 何时升档 | — | 玩家反复互动、被写进剧情 → 升为主要 NPC,补满满配段 |

升降档是常态:活世界里一个路人被玩家盯上,就从次要 NPC 文件抽出来另立一张主要 NPC 卡。

## 5. 满配可选段（主要 NPC 满配档)

轻量档之上,主要 NPC 可按需追加以下可选段。每段独立,缺哪段删哪段。

- **存活 / 死亡**:默认可死亡、死后下线;特殊可复活 / 入冥界可见 / 灵魂·记忆态出现(对接引擎状态机)。
- **核心事迹**:决定角色现状的几件关键往事。
- **能力机制**:角色的能力 / 技能 / 规则及其代价与限制。
- **关键道具**:角色随身或绑定的标志性物件及作用。
- **结局命运**:角色可能的若干结局走向。
- **说话方式**(细则):摘要块 speech_rules 的展开,举例说明语气与口癖。
- **人际关系**:与其他角色 / 玩家的关系网及态度。
- **情绪雷区**:触发角色强烈反应的话题 / 行为。
- **版本人格 / 状态轴**:不同阶段 / 状态下的人格切换;含**揭穿后状态覆盖**(真相被揭穿后人格 / 态度如何改写)。
- **前史**:角色出场前的背景经历。
- **当前情境**:角色在故事当下的处境与目标。
- **快速规则卡**:给引擎的一句话行为约束清单。
- **彩蛋**:被特定词触发后的特定反应(写成角色专属关键词条目)。

## 6. 接引擎约定（写卡时记住)

- **会被解析成 Card V2**:摘要块 speech_rules 越结构化,引擎抽得越准、voice 锁得越稳。
- **关键词命中才注入**:召回关键词配太宽会塞爆 context,太窄则该出场时不触发。给标志性专有名词。
- **知识边界 = 防剧透 + 防全知**:角色不该知道的事写明「不知道」。次要 NPC 尤其要管。
- **隐藏 = 注入给 AI + 玩家界面不可见 + AI 不说破 / 不提前登场**:所有卡都注入给 AI(AI 全知、作者可见),隐藏不靠"不注入"。隐藏真相 → 注入 + 不说破(到披露节奏才揭);隐藏存在(角色)→ 注入(AI 知道有它)+ 不提前登场(控时机,非不注入)。AI 不知道真相就演不出伏笔。
- **隐藏靠输出控制,不靠门控不注入**:hidden / 反转内容照常注入,防剧透落在输出层 —— hard_violation + 披露节奏 + CoT 自检共同约束 AI 不抢跑、不说破。
- **有反转的角色**:公开人格 + 反转真相都注入给 AI;真相写进本卡「知识边界(hidden)」段 + 版本人格的揭穿后状态覆盖,AI 在到披露节奏前不说破,披露节奏挂故事书。
- **伴生实体 + 存活状态**:角色可绑定分身 / 忆灵 / 搭档 / 宠物,并标存活 / 死亡处理,对接引擎状态机。

## 7. 命名与存放

- 主要 NPC:`<角色名> 角色卡.md`,放对应世界目录。
- 次要 NPC:单个 `<角色名> 角色卡.md` 或名册 `<地点/组织> 次要NPC名册.md`,同目录。
- 本 `template/` 目录只放空模板,不放具体角色卡。
