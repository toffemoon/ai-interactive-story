## 核心想法(最重要):固定模板 → 引擎确定性解析,不走 LLM

**现状**:用户上传任意格式文本 → `identify_*` 走 **LLM** 解析成结构化卡。代价:花 token、可能漂移、有摘要上限(73KB 的故事书就超了 → 当初被迫改成确定性解析才跑通)。

**目标**:让用户都通过**建卡系统、用统一模板**建卡 → 卡片格式固定 → 引擎像 `scripts/import_amphoreus.py` 里的 `parse_amphoreus_storybook` 那样**逐字段确定性解析(免 LLM)**:

- 省 token、快、不漂移、忠实保留作者写的字段
- **已验证**:`import_amphoreus.py` 的 `parse_storybook` / `parse_player` / `parse_worldbook` 就是这条路,已跑通(「如我所书」预设就是这么导进库的)
- **两条路并存**:按模板建的卡走确定性解析;用户随便贴的任意格式仍走 LLM `identify_*` 兜底
- **更彻底版**:建卡系统若做成结构化填表,卡直接产出结构化 JSON,连"解析"都省

一句话:**LLM 只在「建卡引导」用一次(把用户的话整理进固定模板);之后存库、开局、运行全程读结构化数据,运行时不再走 LLM 解析。**

## 卡 → 引擎归并(5 类,不是逐卡建 model)

11 类卡归到 5 个「分析引擎」,每类内部分公开 / 隐藏档(详见 `卡片体系总览.md`):

| 引擎类别 | 收哪些卡 | 现状 model |
|---|---|---|
| 角色卡 | 主要NPC · 次要NPC · 隐藏角色卡 | `CharacterCard` ✓ |
| 玩家卡 | 玩家卡 | `PlayerCard` ✓ |
| 世界书 | 世界书 | `WorldBook` ✓ |
| **设定卡** | 地点 · 组织 · 可扩子类 | 🔴 无(现切世界书,提议单开) |
| 故事书 | 故事书 + 事件卡 | `StoryBook` ✓ |

(导演隐藏卡已降级删除:真相并入角色卡 hidden 边界 + 版本人格,披露挂故事书/事件卡)

---

## 一个关键口径:隐藏 = 输出控制,不是不注入

所有卡(含隐藏真相 / 角色 / 事件)**都注入 AI**——AI 全知、作者可见。「隐藏」= ① 玩家**界面不显示** ② AI **输出克制**(不说破真相、不让隐藏角色/事件提前登场)。防剧透靠 `hard_violation` + 披露节奏 + CoT 自检,**不靠"不注入"**——AI 不知道真相就演不出伏笔(知情者的克制、主角的既视感)。详见总览 §二。
