# 长程记忆与状态架构设计

> 状态:设计讨论(未落地) · 日期:2026-06-01 · 作者:yufei
> 来源:与 Claude(Opus 4.8)关于"上千轮长局如何维持设定/状态/记忆一致"的讨论,镜像自 Obsidian 项目笔记。
> 代码引用形如 `story.py:435` 指本仓库当前实现。

## 一、问题

长故事走到上千轮时,角色属性、世界状态、小角色、偶尔人格,全在变。现在的做法(扁平向量记忆 + 每轮注入静态卡)处理不了:

- 派生事实流失、召回不准(例:宁姚躲雨→未受散道→相对强于其他雨后 14 境,这种玩出来的新事实)
- 角色人格会变,继续拿初始卡当 reference 是错的
- 上下文成本:想稳就全量注入设定 = O(n²),长局必爆
- 玩家也会偏离自己的卡

根因一句话:**派生事实没挂在实体上,canon 和散文记忆压在同一层。**

## 二、三个核心判断(把问题重新框对)

1. **三类信息被压在一层**:静态 canon(上传卡/书,不变)/ 情景记忆(逐轮散文,只供口吻连续性,不当事实)/ **派生 canon**(玩出来、需长期生效的新事实)。第三类是核心缺失层。
2. **O(n²) 可绕开**:每轮只注入"在场实体"(present_characters + 当前地点 + 命中世界书/事件),被 scene 大小限界,与故事长度无关。瓶颈是派生事实没挂实体,所以按实体取不出来——修的是挂载。
3. **chunking 难是因为切散文**。按实体/条目切,chunk 本就离散,问题消失。canon 层(结构化、实体为键、可变)和情景记忆层(散文、向量、近期)彻底分开:canon 不需要好的散文 chunking;情景记忆切不准也无所谓,因为它不权威。

## 三、核心架构

**实体活档(per-entity living dossier)** —— 每个实体(角色/地点/势力/物件/世界规则)一份:
- 静态基线(上传来的,不可变,抗漂移锚)
- append-only delta 日志(属性/事实类变化,可累积)
- versioned 画像指针(人格类变化,整块替换,见第五节)

**召回 = 按在场实体取活档**,注入到该角色的 prompt 块。不是按相似度碰运气,也不是全量注入。生造专名靠精确匹配(`_world_keyword_hits` 已有),向量降为"换种说法"的补充。

**consolidation 三层触发**(把贵活挪出热路径):
1. 每轮即时捕获(便宜):走现成 `_store_memory_writes`,写带 entity 标签的 note,立刻可按实体召回。补"长时间连续游玩"的洞。
2. 事件触发(高信号):story event resolved 时(如散道),对受影响实体跑小巩固。
3. 回来时批量精炼(提质):用 `updated_at` 时间差检测"用户回来了"(不是检测空闲——无状态后端盯不住钟),把标签 note 升级成结构化 delta + 矛盾消解。水位线 `consolidated_upto`(照抄 `summary_upto`)。

## 四、关键名词

| 名词 | 一句话 | 形态 |
|---|---|---|
| canon 层 | 仓库:当前为真的结构化设定 = 静态基线 + 派生 | 结构化、实体为键、可变 |
| delta 记录 | 卡片:一条玩出来、长期生效的变化 | `{entity, type(设定/事实), text, source_turn, 置信, 状态(生效/已取代)}` |
| consolidation | 管理员:把原始剧情加工成 delta 入库 | 周期/事件触发,不每轮跑 |

**两个正交的轴**(易混):
- **类型轴(设定/事实)** 管"怎么用、留多久"。设定 = 往后行为规则变了 → 进 canon、实体在场就注入、长期留;事实 = 发生了什么 → 偏情景、可淡出、常是某条设定的出处(provenance)。
- **实体轴** 管"取不取得到"。**召回靠实体轴。** 光分类型不挂实体 = 没解决召回。

引擎现在已有类型轴(`_extract_long_memory` 的 `kind`),缺的是 **entity 字段 + 按实体召回的路径**。

## 五、动态角色卡(必须性:可选,仅 arc 故事)

不要"全动态/就地改写卡"——静态卡兼做**抗漂移锚**,全动态会让角色逐轮漂成通用 AI 腔。真正的问题不是静态 vs 动态,是"哪些能变、多久变、谁控制"。

三个时间尺度:

| 层 | 例 | 可变性 |
|---|---|---|
| 身份脊柱 | 连续性、核心本质、名字 | 不可变(锚) |
| 行为画像 | 性格、价值观、说话方式 | 可变,走离散版本 |
| 情绪状态 | 这场被惹火 | 每轮变(RuntimeState 已管) |

- **一张 versioned 卡,v1 = 上传**;不要两张。OOC **对照当前已提交版本**(转变之间冻住),不对活值——否则 OOC 自我指涉,抓不住渐变漂移,等于废了。
- 切版本:作者谓词(复用 `_check_ending_predicates`)或高闸门 consolidation 提议(涌现转变,要求跨 N 轮证据,倾向作者在环)。
- **红线:不用逐轮 delta 改人格**;属性 append、人格 versioned 整块替换。
- 连带:OOC 检查必须追当前版本;旧版本保留(对比是内容 + 可回退);reroll 天然正确。
- 诚实:平滑连续弧线用离散 waypoint 逼近,不承诺真连续;涌现自动改写是全系统最高风险操作。

**玩家侧 OOC 彩蛋(delight,非承重):** 玩家卡 = 玩家的已提交版本;持续违背 = 玩家侧 OOC。NPC 违背→转性化解;玩家违背→没法转性(用户在拉线)→浮成破壁自我怀疑("是不是被操控")。触发窄(只认人格/本性违背,不认目标漂移/能力越界)、衰减计数、代码武装模型表达、分级慢烧。作者开关默认关;diegetic 版(角色感到外部意志,不破壁)适配题材更广。正常成长(渐进连贯)→给玩家卡切版本;puppeting(尖锐持续矛盾)→彩蛋。复用 OOC 探测器,后做。

## 六、世界书可变性边界

- **世界规则/公理**(法则、世界观:"没有魔法""死亡不可逆")= **不可变**。违背它的内容是 hard_violation,生成时**拒绝**(预防),不是事后 reconcile。
- **世界状态**(桥在不在、哪派控制北方)= 会变,靠 delta。
- 收获:这把"抽象矛盾检测"从昂贵的事后审计降成廉价的生成时预防,退役了大半审计需求。
- 铁律:**delta/consolidation 只动状态和角色,永不碰世界公理;公理只由作者明令改**(剧本写"魔法回归"这种事件,像结局谓词)。

## 七、长程(千轮)问题与对策

| 问题(深度玩家体感) | 对策 | 性质 |
|---|---|---|
| 内容耗尽→叙事变静止 | 检测内容耗尽(主线全 resolved + 结局达成)→ 主动收尾 + 作者寄语 + 引导下一个。无聊要被框成"结局"不是"故障"。寄语兼预期管理(告知后面是自由模式) | 必须,小机制 |
| canon rot(远距离矛盾) | 用到时一致靠区域/实体召回;检测在写路径(读后写);抽象矛盾靠"公理不可变"预防 | 见第六/八节 |
| 投入越深容错越低 | 历史书(大事件防弹脊柱)+ 小细节像人脑淡忘(narratively 认领,别假装完美)+ 时间线可视化 | 必须 |
| 扁平化(都像同一人) | 对比式嗓音审计:抽每角色近期台词判是否分得出,收敛就重申 speech_rules。诚实:只能减缓不能根除 | 后台 |
| 宏观重复(同场景演五遍) | 每场打桥段类型标签 + 近期分布 nudge"换换节奏" | 便宜 |
| 数值饱和 | 朝历史决定的基线衰减(久不互动减,留地板,不归零) | 便宜 |
| 高光选择被遗忘 | 按重逢披露(守卫=实体,"放过他"=delta,重逢=进场=召回);再没遇到=零成本 | 复用召回 |

## 八、历史书

- **两条流**:(a) 主角自己的旅程——玩家是行动者/对象的回合**一律记录**(我的故事,不卡门槛);(b) 世界大事件——重要性门控 + 回溯重打分。
- **回溯重要性 = 因果反向链接(事件版 PageRank)**:每条新 delta 引用某旧事件当起因 → 给那旧事件 `impact_score += 1`(增量、定点)。过阈值 → 回溯晋升进历史书。对上"那次早死是一切的开端 = 大量后续链回它"。
- **不会变 O(n²)**:存一个累加计数器,每条因果链 +1 + 一次阈值判断,**永不重扫**(重扫才是 O(n²))。边界:只增不降(单调,除非接 supersession 减分);+1 只在链真被建时发生(漏链的代价就是不重扫);只算一跳(不做传递记功)。
- 千轮时历史书自己也要分纪元压缩("第一幕摘要")。

## 九、关系/派系图 = 信息流网络(统一 NPC 记忆 + 地图)

**核心统一**:canon 全局完整;关系图把它切成每个 NPC 的"知道视图";同一张图还路由信息怎么流。一图三用途:① 查"NPC X 知道什么" ② 路由"A 知道了还有谁会知道" ③ 可视化。

- **边分类型**:认识 ≠ 信任 ≠ 共享信息。"谁和谁共享"是 **边类型 + 信任值 + 秘密自己的分享规则** 推出来的,不是单存的边。信息沿信任/忠诚 + 派系等级流。
- **跳数封顶**:一跳显式分享 + 派系公告,不做自动多跳流言级联(否则"陌生人怎么会知道"的全知问题)。
- **图会变,知识粘**:未来的信息流用当前的图;已获得的知识不回滚(背叛盟友不会让他忘掉旧秘密);scope 在"扩散那一刻"按当时的图判定。
- **NPC 只知子集,不是整个 canon**——这是 NPC 记忆的全部意义(partial view)。
- **NPC 记忆 = 共享 canon + 每 NPC 知道范围过滤**,不是 N 份独立库。它就是"传播 scope"的读向(传播=写,记忆=读,同一原语)。种子已有:`character_logs.knows`、`facts.hidden/revealed`。
- **位置追踪 = last_known_location**(出场/被提及时更新,不模拟离场游走,有界)。位置=目击=免费知识来源(`present_characters` 已存"谁在场=谁见证")。
- **累计名声**:选择打价值轴标签(仁慈↔狠辣…)→ 代码累计 → 过阈值 → 玩家卡名声 delta。**传播**:名声带 scope(目击者→派系/同地),圈内知圈外不知,便宜版两档,别全知。
- 成本诚实:这是全系统 bookkeeping 最重的一块,靠**分层纪律**(只对反复出现的重要 NPC 建知识视图,只对重要秘密设显式 scope,琐碎事实公开,路人不进)才跑得动。

## 十一、贯穿的统一原语

所有功能收敛到五样底层,不各起炉灶:**实体活档 + 事实上的 scope + 实体构成的图 + provenance 因果链 + 代码侧计数器/阈值**。

- 检测 = provenance + 实体边界(读后写)
- 名声 = 计数器 + 玩家实体
- 传播 = 实体的 scope 字段
- NPC 记忆 = scope 的读向
- 回溯重要性 = provenance 的反向计数
- 关系图/地图 = 实体 + 边的视图

唯一反复出现的软肋:**tag 打得准不准**(实体、因果、价值轴都依赖它)。这是该集中投入验证的点。
