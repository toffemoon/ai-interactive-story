# Phase 3.1 信息传播 —— 设计输入

> **定位**：这是 Yufei 给架构 owner 的**设计输入**，不是决策、不是要求落地。按 2026-06-04 架构主权决策，引擎核心由 Gengyue 设计 + 压测验证才进 main。这份只是把一份**早于 Phase 3 的旧设计**（`长程记忆架构设计` §九，2026-06-01）里跟 Phase 3.1 直接相关的部分抽出来，给做 3.1 时参考。
>
> 起因：Phase 3 设计文档把"场外被告知/转述/可推断"押到 3.1，注「没有低成本现成解，参考矮人要塞 rumor」。这份提供一个**有界、且复用 3.0 现有字段**的思路，供评估。

## 一、一句话核心

**Phase 3.1 不必是一套新系统——它是 Phase 3.0 那个 `knowers` 字段的「写向」。**

- Phase 3.0：`knowers` = 事实建立那刻的在场集；读的时候按发言角色过滤。这是**「记忆 = 读」**。
- Phase 3.1：A 把某事**告诉**了不在场的 C → 就是**往同一条事实的 `knowers` 里加 C**。这是**「传播 = 写」**。

> **传播 = 写，记忆 = 读，同一原语。** 共场（3.0 已覆盖）和转述（3.1）只是同一个 `knowers`/scope 字段的两种写法，不是两套机器。这把 3.1 从"新系统"降成"给同一字段多一条写规则"。

## 二、有界的传播规则（避开"多跳流言=全知"）

旧设计 §九 的取舍，直接对症 Phase 3 文档担心的"多跳级联→陌生人怎么会知道"：

1. **信息沿信任 / 忠诚 + 派系等级流**——不是谁都往谁传。
2. **跳数封顶：只做「一跳显式分享」+「派系公告」，不做自动多跳流言级联。**
   - 一跳显式分享：A 明确告诉 C（当面=3.0 共场已覆盖；**场外/私下** = 3.1 要补的那一跳）。
   - 派系公告：广播给一个派系 = 把该派系成员加进 `knowers`（一次写、有界）。
3. **scope 在「扩散那一刻」按当时的关系图判定**；**知识粘**：已获得的知识不回滚（背叛盟友不会让他忘掉旧秘密）。
4. **分层纪律**（成本可控的前提）：只对**反复出现的重要 NPC** 建知识视图、只对**重要秘密**设显式 scope；琐碎事实默认公开、路人不进。

## 三、复用的现有种子（为什么不算从零起）

旧设计标注的、引擎里**已有**的挂载点：

- `present_characters` —— "谁在场 = 谁见证"，3.0 的 `knowers` 已经在用。
- `character_logs.knows` —— 每 NPC 的"已知"列表，可作 per-NPC 知道视图的载体。
- `facts.hidden / revealed` —— 事实的可见性种子。
- 关系 / 派系数据（`relationships` / `faction` 字段）—— 传播路由的图。

即：3.1 的"写向"主要是**在已有字段上加一条「显式分享 → 写 knowers」+「派系公告 → 批量写 knowers」的规则**，再复用 3.0 的读向过滤 + Phase 1 认忘，不需要新存储层。

## 四、建议的最小落地（去风险，供评估）

按"先确定性、后判断密集"排，跟 Phase 3.0 的取舍一致：

1. **3.1-a（确定性、几乎免费）**：派系公告 / 显式群体分享 → 批量写 `knowers`。纯集合写，无额外 LLM。
2. **3.1-b（要一点判断）**：场外/私下"A 告诉 C"的检测 —— 需要识别"分享"这个动作。这是判断密集、易出错的部分，**建议门控 + 压测后再上**。
3. **押后**：可推断（C 没见证但能推理）—— 旧设计也没给低成本解，留更后。

## 五、诚实的边界（Yufei 自评，别当成"已成立"）

引用旧设计 §十四 的自我批评，这份**不回避**：

- **这是全系统 bookkeeping 最重的一块**（每事实带 scope、每次生成过滤 + 现在还要加写向）。
- **一切赌在 tag 准不准**：识别"谁告诉了谁""属于哪个派系"依赖 LLM（DeepSeek 在结构化判断上偏弱）。tag 不准 → scope 写错 → NPC 知道了不该知道的（剧透）或不知道该知道的（失忆）。
- **未验证**：整套是设计层、没跑过压测。按治理规则，要架构 owner 评估 + 压测（缺席认忘不退化、在场不回退、剧透率、成本）才谈落地。
- **机会成本**：旧设计 §十四 头号弊端——这套为"上千轮"设计，先确认真实玩家轮次分布值不值得做这层。

## 六、给架构 owner 的一句

Phase 3.0 的 `knowers` 已经把"记忆=读"做出来了；3.1 的"传播=写"是同一字段的另一半，用「一跳 + 派系公告」框住就不全知。**如果 3.1 排期，这条「同一字段双向」+「一跳封顶」也许能把你注的"没有低成本解"降一档**——但 tag 准确度和成本得用你的 eval 矩阵实测，设计层说了不算。

完整原始设计见 `[[长程记忆架构设计]]` §九（信息流网络）+ §十一（统一原语）+ §十四B（NPC 记忆弊端）。
