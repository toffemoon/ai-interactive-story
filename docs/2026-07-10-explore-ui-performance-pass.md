# 探索页 UI 与性能优化

> 日期:2026-07-10
> 范围:`frontend-next` 探索页、通用卡片和前端路由加载。
> Linear:[YOR-210](https://linear.app/yorha/issue/YOR-210/optimization-explore-ui-and-performance-pass)

## 先看结论

探索页从“筛选项松散、卡片一口气全加载、主包过大”调整成更紧凑的内容货架。没有改故事引擎和视觉方向,也没有给每张卡堆 WebGL 或重型 3D 动画。

- 主 JS:568.70 KB → 393.88 KB,下降约 30.7%。
- 主 JS gzip:195.06 KB → 133.95 KB,下降约 31.3%。
- 探索页拆成独立 chunk:9.42 KB,gzip 4.14 KB。
- 桌面 6 列、手机 2 列、横屏 3 列;三个视口都没有页面级横向溢出。

## 页面盘点

按可复用功能算,截图里的首屏有 8 组 UI:全局导航、页面标题与计数、内容类型、搜索、排序、题材筛选、卡片货架、继续游玩入口。按首屏实际可见单元算约 50 个以上,主要来自 15 张卡片及其类型/官方角标。

适合优化的动效有 7 类:路由加载、筛选滑块、数字切换、结果切换、卡片翻面、封面加载/悬停、详情弹窗。本批全部做了约束:只动 opacity/transform,遵守“减少动态效果”,列表不做逐张重型入场。

## 已完成

- 所有页面改为按路由懒加载,增加稳定的路由加载占位,消除原先大于 500 KB 的主包警告。
- 筛选区收成类型、搜索、排序三段工具栏;只显示真实可用的“综合 / 最新”,题材保持单行横向滑动。
- 搜索使用 deferred value,输入时不阻塞文本框;增加一键清空和实时匹配数量。
- 数据加载并行化并使用 skeleton;真正的请求失败显示重试,不再伪装成空书架。
- 每页固定 15 张;桌面扩大到 6 列。分页后自动回到结果顶部,减少长页面来回滚动。
- 卡片封面改为真实 `img`:首屏前 2 张优先,其余 lazy loading + async decoding;加载失败退回结构化书脊占位。
- 卡片鼠标光斑更新限制为每帧最多一次;封面只做轻微缩放,不引入持续 RAF、shader 或 WebGL。
- 卡片正面是完整可聚焦按钮;翻面后焦点进入返回按钮,Esc 返回封面,不可见一面退出 Tab 顺序。
- 角色详情补齐焦点陷阱、Esc 关闭、背景滚动锁定和关闭后的焦点恢复;桌面图文并排,手机自动堆叠。
- 加入筛选滑块、数量、结果区和弹窗的轻动效;系统开启减少动态效果时全部退回静态。
- React Router v7 future flags 已启用,刷新后控制台没有新错误或警告。
