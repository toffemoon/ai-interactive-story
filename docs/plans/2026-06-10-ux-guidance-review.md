# ai-interactive-story 前端用户体验审查报告

> 数据来源:对 recon 前端(桌面 + 移动)五个视角(first-run / story-journey / chat-create / account-mine / feedback-states / mobile)的逻辑审查发现,已合并跨视角重复项。

---

## 一、新手旅程急救清单

8 条 high 影响、改动小、见效快的修复,按新手动线顺序排列。

### 1. 开屏四按钮殊途同归,「游客模式」是假承诺
- **在哪**:ReconTitle 开屏(app.jsx:2691-2698, ReconTitle.jsx:225)
- **用户卡在哪**:「开始旅程 / 登录注册 / 游客模式 / 继续游戏」四个入口的回调全部 = `setLoginShown(true)`。专为避开注册点「游客模式」的玩家撞上邮箱+验证码注册墙,觉得被骗直接流失;「继续游戏」对无存档新人也是死链接。
- **怎么改**:最低成本——删掉或改名「游客模式」;「继续游戏」仅在本机有存档/已登录时显示。理想——onGuest 走免登录会话。
- **建议文案**:若保留按钮,点击时先提示「测试阶段需邮箱注册后游玩,注册只需 30 秒」;真游客则提示「游客进度只保存在本机,不跨设备」。

### 2. 登录卡「回到故事 / 初次到来」是暗语,新人找不到注册
- **在哪**:LoginView 登录/注册 tab(app.jsx:1340-1366)
- **用户卡在哪**:默认落在「登录」tab,注册藏在文学化的「初次到来」里,没有「登录 / 注册」字样;第一次来的人填邮箱密码点「进入故事」只会得到失败。另外整卡没有「忘记密码」出口。
- **怎么改**:tab 文案点明功能;从「开始旅程/游客模式」进入默认选注册 tab,从「登录注册/继续游戏」进入默认登录 tab;登录 tab 下加「忘记密码?」链接。
- **建议文案**:「登录 · 回到故事」「注册 · 初次到来」(保留韵味同时点明功能)。

### 3. 「涟漪入局」之后故事不开演,新手对着静态 premise 发愣
- **在哪**:ReconPlay 第 0 回合(app.jsx:1132, ReconPlay.jsx:317)
- **用户卡在哪**:入局后只有 premise 文本+空选项栏+空输入框,故事不自动开场。「空着点执行 = 生成开场」这个隐藏能力(runTurn 对 turns.length===0 放行)只在无 premise 的兜底文案里提到,有 premise 的正式故事永远看不到;唯一提示是一行小灰字。
- **怎么改**:「涟漪入局」后自动 runTurn() 生成开场(loading 复用现有「叙事生成中……」);或 turns 为空时把「执行」换成醒目主按钮。
- **建议文案**:「✦ 开启序幕——点击让故事先演给你看,或直接说出你的第一句话」。

### 4. 创作桌输入框是伪 placeholder,提示语会和用户输入一起发给 AI
- **在哪**:ReconCreate.jsx:289-295(contentEditable span)
- **用户卡在哪**:提示语「用一句话告诉我下一步……」是真实 DOM 文本:点击后光标插在提示语中间,打字混在一起,回车把整句垃圾发给 /api/build_card;每次发送后提示语复活,每条消息都要手动全选删一遍;输入文字还沿用浅灰提示色,像没输入成功。
- **怎么改**:换成真 input/textarea + placeholder 属性(ReconChat/MCreate 已是这种做法,样式照搬);若必须 contentEditable,用 `:empty::before { content: attr(data-ph) }` 显示提示;发送前 trim 并拦截与提示语相同的内容。
- **建议文案**:placeholder 原文保留即可,关键是别让它进 textContent。

### 5. 游玩页顶栏五个死按钮:重生成有现成 API 却没接线
- **在哪**:ReconPlay.jsx:269-279(存档/回溯本轮/重生成/SUPERVISOR/齿轮)
- **用户卡在哪**:全部 cursor:pointer 但没有任何 onClick。玩家对上一轮不满点「重生成」毫无反应;点「存档」无反馈以为没存。而 StoryPanel 的 rerollLast() → /api/reroll 真实存在,自动存档也真实存在。
- **怎么改**:把 rerollLast 作为 prop 传给 ReconPlay 接到「重生成」(busy 时置灰);「存档」点击弹 toast 或改成状态指示文字;「回溯本轮」「SUPERVISOR」「齿轮」未实现就先隐藏。
- **建议文案**:存档处显示「已自动存档 · 第 N 回合,可随时离开」。

### 6. 「新建对话 NEW CHAT」点了跳创作桌
- **在哪**:ReconChat.jsx:277
- **用户卡在哪**:想和当前角色重开一段对话,onClick 却是 `onNav("build")`,被扔进造卡页面,不知道为什么也不知道怎么回去。同页顶栏「记忆 MEMORY」跳游玩页、「档案 ARCHIVE」跳个人中心,文案与去向全部对不上。
- **怎么改**:要么实现本义(重置当前角色的 sidsRef/openedRef/byKey 触发新开场),要么改文案如实表意;「记忆/档案」改成实际去向的名字或暂时移除,导航词汇全站与 ReconRail 保持一致。
- **建议文案**:「创造新角色 CREATE CHARACTER」(若保留跳创作桌的行为)。

### 7. 聊天/创作发送后零等待反馈,新手以为卡死狂点
- **在哪**:app.jsx:2229-2243(创作 send)、2187-2203(聊天 send),busy 未传给 ReconChat/ReconCreate/MChat/MCreate
- **用户卡在哪**:LLM 回复要 5-30 秒,期间无「正在输入」指示,发送键照常亮着,再按 Enter 被静默吞掉(输入框文字还在但毫无反应)。旧 CardBuilder 有「推演中…」气泡,recon 版把这层反馈丢了。
- **怎么改**:把 busy 传入各视图:聊天页角色侧插入动效 pending 气泡(自动开场已有「……」占位,复用同一机制),创作桌恢复「执笔人推演中…」行,busy 时发送钮置灰;busy 中回车提示「请稍候」而非静默忽略。
- **建议文案**:「TA 正在落笔…」(聊天)/「执笔人推演中…」(创作)。

### 8. 手机软键盘整条盖住输入框,核心循环打字看不见字
- **在哪**:ReconMobile.jsx MShell 底部输入条(.m-foot),游玩/聊天/创作三页共用
- **用户卡在哪**:.cv-m 是 fixed inset:0,viewport meta 无 `interactive-widget=resizes-content`,全工程无 visualViewport 监听——iOS Safari 及 Chrome 108+ 键盘弹起会盖住输入框和「执行/发送」按钮。
- **怎么改**:index.html viewport 加 `interactive-widget=resizes-content`;再用 visualViewport resize 事件把 .m-foot 抬到可视高度兜底 iOS;改完真机 iOS Safari + Android Chrome 各验一次。
- **建议文案**:无需文案,纯布局修复。

## 三、引导体系建议

这是文字冒险产品,氛围即卖点——引导应该像舞台提词,出现一次、说一句话、说完退场。不做分步遮罩教程,不做打断式弹窗轰炸。需要四类引导,各自对应审查中暴露的断点:

### 1. 首次进入:用「副标题」管理预期,而非教程
开屏按钮和登录卡的问题本质是**承诺与去向不符**,解法是在选择点旁边放一句话,而不是事后教学。
- **形式**:按钮副标题 / 卡片顶部一行说明。
- 开屏:「开始旅程——需要一个账号,30 秒注册」「游客模式——无需注册,进度不跨设备」(若做真游客)。
- 登录卡:tab 直白化(「登录 · 回到故事」「注册 · 初次到来」),按入口预选 tab,本身就是最好的引导——用户根本不需要被教。
- 个人中心:「仅本机」角标 + 区块底一行「登录后的对局会跟随账号;标记『仅本机』的存档只保存在当前浏览器」。**存档归属是全站唯一需要主动解释的概念**,一行说明放在它出现的地方即可。

### 2. 首局开场:让产品自己演示自己
游玩页的最佳引导是**自动生成开场**——故事先演一段,玩家自然明白「我说话,世界回应」的循环,胜过任何教程。在此基础上:
- **形式**:首回合一次性内嵌说明文字,看过即消失(替代已拆除的 coach 四步引导)。
- 输入框上方一句:「不知道写什么?直接点开始,故事会先演给你看」;
- 右侧状态区(世界状态/事实边界)首次展开时各一行灰字说明用途;
- 选项与自由输入的关系用一句话点破:「选项只是建议,你随时可以说出自己的行动」。
- 不建议恢复完整多步 coach——信息密度问题应优先靠隐藏死 tab、删「⚡0」这类减法解决,而不是用引导解释不该存在的东西。

### 3. 空状态:每个空态必须带一个可点的出路
审查里所有空态(聊天无角色、成就为空、新号统计为 0、书架为空)的共同问题是「解释了为什么空,但没说去哪」。
- **形式**:空态面板 = 一句氛围文案 + 1-2 个按钮(复用 cv-gempty 样式),不要纯文字。
- 聊天空态:[去创作角色] [去故事库逛逛];成就空态:首个成就名+条件+入口;新号统计 0 旁:「去创作你的第一张卡 ›」。
- **前提**:先修掉两个污染空态的 bug——自动注册的 0 回合空存档(让真空态有机会出现)和静默 catch 伪装空态(失败要长得像失败:「加载失败,点击重试」)。

### 4. 等待反馈:动效占位,不是文字解释
LLM 产品 5-30 秒的等待是体验主体之一,缺反馈的代价是「狂点 + 以为坏了」。
- **形式**:统一一套 pending 语汇,全站三处复用——聊天「TA 正在落笔…」(角色侧动效气泡)、创作「执笔人推演中…」、游玩「叙事推演中…▋」(带光标动效),配合按钮置灰/文案变「生成中」。
- busy 中回车给「请稍候」轻提示而非静默吞掉;开场失败给「重试」可点。
- 这一类不算「引导」胜似引导:它告诉新手「系统活着、你的操作生效了」,是所有引导里优先级最高、最不打扰的一种。

**总原则**:本次审查的 high 项里,大部分不是「缺引导」而是「界面在撒谎」(假按钮、假承诺、假空态)。先让每个可点的东西说真话,引导体系只需要在四个断点各补一句话。
