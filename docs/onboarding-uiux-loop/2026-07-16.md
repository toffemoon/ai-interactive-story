## 轮 1 · 逐字党(慢读久停)· 桌面 1600×1000

**环境**:后端 uvicorn:8000(重起,200 正常)· 前端 frontend-next-ob:5185 · 真 Chrome · `/#/test`。

**走查**:名字(「我就叫小满」本地过)→ 头像(你帮我选一张)→ 口味(「最近在看《解忧杂货店》」,走 AI)→ 办卡(落章 + AI 寄语 + 整卡翻转)→ 故事导览(书卡 demo:灵魂摆渡人,封面正常)→ 门/宣双人对话(和宣打招呼、问一句「你平时都在补什么书?」,宣 AI 正常回)→ 休息区/创作投射 demo → 收尾(去故事广场看看 / 我自己逛逛)。全程走完。

**发现**

| # | 严重度 | 现象 |
|---|---|---|
| 1 | 低(已修) | `.home-ob-nexthint`「点一下继续」弱提示 `rgba(241,231,214,0.42)` 无描边,在明亮/繁杂立绘背景上糊掉。而这条提示恰恰是给「久读不点」的慢读者(逐字党)准备的(`obContinueHint` = 长时间不点 chip 触发),对它最想帮的人反而不可读。 |
| 2 | 记录 | 每拍气泡入场 `obBubbleIn` 有 380ms 延迟 + 320ms 淡入(设计:先换姿势后出气泡)。逐字党无碍,但截图/自动化读 opacity 会在延迟窗口内误判为 0 —— 这是驱动侧注意点,非缺陷,不改。 |
| 3 | 记录 | 「跳过」skip 在气泡内(cream 底 + `rgba(32,32,29,0.5)` 深字),对比尚可、有 hover 提亮。暂不动(是否要让人更容易跳过属产品方向,留雨钦定)。 |

**假象排查(留给后续轮的教训)**:本轮一度以 `*{animation:none}` 全局冻结截图,污染了 CSS 动画时间线,导致气泡卡在 `obBubbleIn` 0% 帧(opacity 0、translate −320)、书卡卡在换场绿底 —— 都是自造假象。真 Chrome 里 rAF 正常,**别再全局冻结**,靠自然 settle + 等待即可。另:`getComputedStyle().opacity` 对 animation 驱动的透明度会返回基态值(常读到 0),**以截图为准**,别信 JS 读的 opacity。

**修了什么(1 个)**
- `frontend-next/src/routes/Home.css` `.home-ob-nexthint`:alpha `0.42 → 0.68`,加 `text-shadow: 0 1px 3px rgba(0,0,0,0.55)`。仍比选项 chip 弱(次级、无描边),但任意背景可读。

**验证**:真 Chrome 同拍 zoom 对比,提示明显更清且不喧宾夺主;`npm test` 72/72 绿;`npm run build` 重建 dist 通过。

**留给雨钦**
- 发现 2/3 只记录未动。若想让「跳过」更显眼,是产品方向决策,等你定。
- 台词里有个细节(非本轮修域):口味输入含书名号时,导览拍模板 `说到「${taste}」` 会出现 `「《解忧杂货店》」` 双层括号。属台词/文案润色域,留你处理。

## 轮 2 · 好奇宝宝(每拍在底部输入框插话)· 桌面 1536

**环境**:后端 8000(复用,200)· 前端 frontend-next-ob:5185(**上一轮后被回收,本轮重起**)· 真 Chrome · `/#/test`(清 `ais_home_v1`/`ais_ob_echo_v1`/`ais_onboarded_v1` + 硬刷 `location.reload()` 才从 intro 从头走 —— `navigate` 到相同 hash 不会 reload、React 内存态不重置,这是驱动侧坑,记一下)。

**本轮重点**:压分支头号特性「可插话长链」—— 在多个拍插话提问,验糖沐/宣是否在角色内接住、流程不被带歪、脚本 chip 能续链。

**走查 + 可插话验证(4 处,全过)**
| 插话点 | 输入 | 结果 |
|---|---|---|
| name(field) | 「等等,你叫什么名字呀?」 | 判 [CHAT],糖沐答「我叫糖沐…由我来帮你登记就好啦」,**不误登记**,仍停 name、卡仍「待登记」。 |
| tryStoryIntro(导览,非 field) | 「这些故事都是谁写的呀?」 | 糖沐答「有些是客人留下的,有些是我们自己写的…」,**不推进**,「拿一本看看」chip 仍在。 |
| tryChatTalk(宣,interruptible) | 「宣,你手里拿的是什么书?」 | 宣在角色内答「《溪山行旅图》的摹本,刚补好一页。」,脚本 chip「听糖沐解释」仍在**能续链**。 |
| tryChatGreet(xuanLine field) | 「你补书的时候会难过吗?」 | 宣答「修补破页…有一点点心疼啦,但…就又觉得挺好的。我还有事,先回去了。」,正常推进 tryChatLeave。 |

全程零横向溢出;完整走到收尾,点「我自己逛逛」**干净退出到正常首页 galgame**(糖沐留场、UI 切首页工具栏 + 「开始故事」);app 层无 console error(仅 3 条浏览器扩展噪音 "message channel closed")。**可插话长链 = 稳,本轮未发现该特性缺陷。**

**发现**
| # | 严重度 | 现象 |
|---|---|---|
| A | 环境·重要 | **claude-in-chrome 的 tab 是隐藏运行的**(`document.visibilityState === "hidden"`、`hidden:true`、`hasFocus:false`)。Chrome 对隐藏 tab 暂停 rAF(实测 4s 内 rAF 回调 **0 次**)、把 setTimeout 钳到 ~1000ms(`setTimeout(100)` 实测 ~996ms)。**后果**:① 一度把首页「主线程被占 90%」当 perf bug —— 是隐藏 tab 假象,已排除;② 一路截到「气泡卡在淡入中途」也是同因(rAF 动画在被节流的时间里跑,wait 不够)。**这个 loop 恰好踩进它自己警告预览 pane 的坑**。可靠:布局/结构/溢出/DOM 状态/交互逻辑 + CDP 截图(截图强制渲染)。不可靠:动画时序手感、perf 探针。轮 1/2 的布局与逻辑结论都靠 state 读 + 截图,**仍成立**。 |
| B | blocked | **手机窄屏 390 测不了**:窗口最大化,`resize_window(390,844)` 报成功但 viewport 恒为 1536(屏本身也仅 1536 CSS px);claude-in-chrome 无 CDP device emulation,伪造容器宽度触发不了 `@media`/`usesFlowOnboardingBubbleLayout` 的 viewport 判断。响应式这一整块本环境测不了。 |
| C | 建议 | 单气泡 VN 式:好奇宝宝插话后,**自己那句问题不回显**,只显角色回复。多轮追问时略缺「我问了啥」的确认感。属交互模型/产品方向决策,未改,留你定。 |

**修了什么**:**0 个**。可插话特性本轮验证是稳的,没发现高把握的前端缺陷;按「拿不准/需决策就别修、记日志」执行,不硬造改动。

**留给雨钦(要紧的在前)**
1. **发现 A(环境)最要紧**:本 loop 现在跑在隐藏 Chrome tab 里,**动画时序 / 手感 / perf 这几维测不了**(正是 loop 想测的)。若要测这些,得让 Chrome 窗口在循环期间处于前台可见(`visibilityState:"visible"`);否则本 loop 实际只能覆盖布局/结构/交互逻辑。请你定要不要调环境。
2. 发现 B:手机 390 需真机 / 支持 device emulation 的环境,本环境做不到。
3. 发现 C:插话不回显自己的话,是否要补,看你。
