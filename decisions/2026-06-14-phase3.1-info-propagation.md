# Phase 3.1 信息传播(非感知知识)方向定调 + 落地前提

架构 owner 审阅 team 仓 [PR #15](https://github.com/yorhagengyue/yorha-a2-team/pull/15) 的设计输入后定调。本文是**决策记录**(decision），不是落地设计；落地设计落到 `docs/design/` 时再展开。

## 一、背景

Phase 3.0（每角色知识边界）已上线：每条派生事实带 `knowers`（建立那刻的在场实体集），读路径按"当前发言角色"过滤、缺席角色看不到 → 走 abstention 认忘；并有"点名问某角色一件他不在场的往事 → 确定性把这条从他视野删掉"。核心信条:**靠提示让模型自律不稳,只有"名字在不在在场名单"的确定性是/否才稳**;`knowers` 是纯集合过滤、~0 额外 token。

Phase 3.0 文档已押后**非感知知识传播**:① 场外被告知 / 转述 / 留信(共场覆盖不了)② 可推断。PR #15 是给这块的设计输入。

## 二、决定

1. **3.1 = `knowers` 字段的「写向」**。3.0 = "读 knowers = 记忆"(建立时记在场集、读时按发言角色过滤);3.1 = "写 knowers = 传播"(A 把事告诉不在场的 C → 往同一条事实的 `knowers` 集 `add` C)。**同一原语,双向**;不新建系统、不加存储层、读向完全不改。

2. **3.1-a(派系公告 / 群体显式分享)= 确定性纯集合写、~0 token → 优先排期**。延续 `knowers` 的集合操作特性,符合"确定性是/否"信条。

3. **3.1-b(场外私下"A 告诉 C"的检测,依赖 LLM 识别"分享"动作)= 不稳 → 门控 + 压测达标后再上**,不与 3.1-a 同批。这是退回"赌 tag 准"的支路(DeepSeek 结构化判断偏弱),必须隔离 + eval 把关。

4. **流言级联用「一跳封顶 + 派系公告」框住**,不做自动多跳级联(避开 Dwarf Fortress 式 rumor 爆炸)。分层纪律:只对重要 NPC / 重要秘密建视图,路人默认公开。scope 在扩散那刻按当时关系图判定;知识粘(已获知识不回滚)。

## 三、理由

- 贴现有信条:**确定性是/否 > 劝模型自律**;3.1-a 是 `knowers` 集合写的自然延伸,零 token、可回归面小。
- 把 3.1 从"新系统"降维成"给同一字段加一条写规则",是真有价值的降本判断。
- 主动规避调研明确警告的**过度复杂化**(多跳 rumor 最易爆炸)。

## 四、落地前提(未满足不进 main)

1. **over-abstention 当独立失败模式补对照测法**。PR #15 只展开了过度泄漏(剧透)方向;漏检一次"分享"动作 → C 本该知道却 abstain(该传没传到 → NPC 失忆),症状还会与 Phase 3 缺席认忘混淆、难归因。需专门对照场景:A 私下告诉 C → 换 C 发言应能引用 / 旁观 D 仍 abstain。
2. **设计引用字段名对引擎现 schema 核实**。PR #15 把 `present_characters` / `character_logs.knows` / `facts.hidden·revealed` / `relationships·faction` 当"已有挂载点";3.0 实际落地的是 `knowers` 集合。这些挂载点是否真存在,决定"不算从零"的前提是否成立 —— 落地前对引擎实况核一遍。
3. **"先确定性删、后又被告知"的恢复边界落定**。Phase 3 有"点名问缺席往事 → 确定性删出视野";3.1 写向是反向(确定性加入)。按"知识粘不回滚"精神应恢复,但这是 PR #15 未点明的边界,落地时定。

## 五、范围与遗留

- **不解决**:确定性删除遗留的两条短路径(近期原文 + 全角色共享摘要)未盖知识边界 —— 与本决策**正交**(那是 3.0 删除向的已知遗留,本决策是写入/传播向)。但二者症状会叠加(3.1 写 knowers 让 C 知道 vs 短路径泄漏让 C 提前知道),排查时心里有数。
- **继续押后**:可推断(C 没见证但能合理推理出)。
