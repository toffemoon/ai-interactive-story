# 提案:预设开局计数,支撑探索页「热度」排序

## 背景

探索页改版已上前端(商城式:故事书/卡 二级切换 + 标签分类 + 搜索 + 排序),排序组规划「综合 / 按时间 / 热度」三档。前两档已上(按时间靠 list 端点只读透出 `updated_at`,见同 PR 单独 commit);**热度没有数据源** —— presets / cards 没有任何游玩计数,前端不造假数据,v1 不上热度按钮。

## 提案(最小版)

- `presets` 表加 `plays int not null default 0`(或独立轻量计数表,避免动主表 —— 落点你定)
- 以预设开新局时 +1:入口在 api 层 session 创建/首回合处识别 preset 来源
- `/api/presets` 列表透出 `plays`;前端热度排序 = `plays desc`,字段一到前端即可接(排序 UI 已留位)
- 卡的热度后置(卡被导入创作的计数,粒度更碎,价值待定,不在本提案)

## 边界

- 数据层 / 引擎 = Gengyue 决策域,本文件只是提案;字段名 / 落点 / 迁移文件由你定
- 计数不需要实时精确,丢计数可接受(无事务/锁要求)
- PROD schema 对齐纪律(2026-06-09):若加列,迁移文件 + schema.sql 同步走你的流程
