# 卡模板微调(2026-06-08)+ 引擎对应改(给 Gengyue)

> Yufei 这轮对 `card-templates/` 做了三处微调(内容 / 设计域),引擎要对应跟一下。三处都跟之前 P0 同向、不冲突。

## template 改了什么(已在本 PR 的 `card-templates/`)

1. **主要NPC 默认完整** — `主要NPC 模板` 不再分轻量 / 满配档,模板把全部段(引擎摘要 + 正文 + 满配段:存活死亡 / 核心事迹 / 能力机制 / 关键道具 / 结局 / 说话细则 / 人际关系 / 情绪雷区 / 版本人格 / 前史 / 当前情境 / 快速规则卡 / 彩蛋)列全;作者没填的留空。
2. **取消次要NPC 独立卡** — `次要NPC 模板` 改成说明卡。一般 / 路人 NPC 并入所在地点 / 组织设定卡的「NPC 原型」区(地点 §4 / 组织 §6,已有);具名且需展开的直接升主要NPC。起因:中间档实测易成空壳(「匹诺康尼校园 次要NPC」)。
3. **设定卡加「通用」子类** — 新增 `设定卡 模板·通用`,覆盖组织 / 地点之外的中层设定(阵营 / 物品 / 历法 / 种族 / 概念 / 事件背景)。骨架 = 引擎摘要 + 概览 + 自由分段 + 钩子。

## 引擎对应要改什么

| template 改动 | 引擎对应 | 跟 P0 的关系 |
|---|---|---|
| 主要NPC 默认完整 | `CharacterData` 承接满配段字段(存活死亡 / 能力机制 / 关键道具 / 结局 / 情绪雷区 / 前史 / 人际关系… 现都没字段)+ `parse_character` 解析这些段 + 引擎注入 + **`build_card` 建卡(创造)也要支持填这些满配段**(否则作者对话建卡填不进、产物缺段,详情/导入也就没数据) | = P0-1「角色卡扩字段 / 承接全字段」+ P0-2「build_card」具体清单 |
| 取消次要NPC 独立卡 | 不再需要「次要NPC 名册卡」解析路径;NPC 原型随**设定卡引擎**一起消费 | = P0-1「设定卡独立引擎」+ **P0-3 转向**(见下) |
| 设定卡加通用子类 | `SettingCard` 已有 `category` / `sections`(任意标号段),通用子类**基本不用加字段**,`parse_settingcard` 认 `类别: 通用` 即可;dedicated 设定卡引擎照常 | = P0-1「设定卡独立引擎」覆盖 |

> **P0-3 转向**:`2026-06-06`/`P0` 里那条「次要NPC 名册解析」随本次「取消独立卡」**作废** —— 不再补名册解析器,改为 NPC 原型并入设定卡引擎消费。

## 主要NPC 满配段字段名(前端已先行,扩 model 请用同名)

前端编辑器 / 草稿**已经按这套字段名做上满配段**(存 `characters` kind,`/api/library/save` 保留原始 dict,引擎暂忽略未知字段、不报错)。你扩 `CharacterData` 时**请用同名**,作者已填的满配段数据就**自动接上**,不用迁移。

| 满配段 | 字段名 | 类型 |
|---|---|---|
| 存活与死亡 | `survival` | str |
| 核心事迹 | `deeds` | str |
| 能力 / 机制 | `ability` | str |
| 关键道具 | `items` | str |
| 结局 / 命运倾向 | `fate` | str |
| 说话方式细则 + 例句 | `speech_detail` | str |
| 人际关系 | `relations` | str |
| 情绪雷区 / 触发点 | `triggers` | str |
| 前史 | `backstory` | str |
| 快速规则卡 | `quick_rules` | str |
| 彩蛋触发 | `easter_eggs` | str |

(版本人格 `versions`、当前情境 `scenario` 已在 model,沿用。)`build_card` 产出也请填这套字段,否则对话建卡填不进。
