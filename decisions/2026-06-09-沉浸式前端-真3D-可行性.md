# 决策草案:真·自由漫游 3D 可行性(沉浸式前端)

> 你要的"先调研真 3D 再写 decision"。结论先放最前。

## 裁决
**可行,但不该当 v1;而且当前愿景里没有任何元素真正"需要"自由漫游 3D。**
- "自由漫游 3D" = 用户自己驱动镜头在连续空间里走 + 角色**身体转过来面对你**。技术上能在这套栈上为一个**极小场景**做出来,但**真正的杀手是国产中低端安卓(+ 微信内置浏览器)的发热/掉电/热降频 + 国内分发(GFW)**,不是渲染本身。
- **逐元素分析:零个愿景节拍真的强制自由漫游 3D**(见下)。你描述的其实是"受控镜头的电影感场景 + 一两个会动的角色"——那是**预渲染图序列 + Live2D**,不是 Three.js 自由漫游。
- 唯一真正触发 3D 的,是"OC 整个身体转过来面对你"——而**连这个都更适合用一个优化过的 hero 模型或一段预渲染转身**,而不是一个自由漫游世界。

## 逐元素:谁真需要自由漫游 3D(= 空集)
| 愿景节拍 | 真需要自由漫游 3D? | 更便宜的做法 |
|---|---|---|
| 推门→走进→镜头到糖沐 | 否 | 预渲染图序列 scrub 到 canvas(你愿景自己写的 分镜→AE) |
| 糖沐收银台(商城/搜索/充值) | 否 | 2D 立绘 + 对话框,纯 React/CSS 复用 StoryPanel+SSE |
| 书架=我的 | 否 | 现有 MineView 换皮(Phase3 皮肤,同数据) |
| 侧门→进游玩 | 否 | 一个全屏 GLSL 涟漪/溶解着色器(几 KB)+CSS 兜底 |
| 创作桌·坐 OC 对面看实时变化 | 否(最像但不是) | **Live2D**(固定镜头 + 单角色面对面,教科书用例) |
| 玩家 CN 走动 | 否(且愿景里还未定/可选) | 固定俯视镜头下的 2.5D sprite |
| 手机/点角色 | 否 | 纯 2D 面板 |

**自由漫游 3D 是产品愿望,不是工程必需。** 只有当你判定"**自由漫游这个体验本身**(摇杆在连续空间走 + OC 在 3D 里转身)就是产品的非妥协卖点"时,它才从"没元素需要"变成"体验需要"——**这是设计决定,不是工程决定**(下面"唯一会翻盘的决定")。

## 真要做,得付什么
- **一条隔离的 Vite 打包路由**(现零构建 in-browser Babel 塞不下 Three.js;Three 不 tree-shake,~320–590KB);第二套前端工具链 = 永久运维分裂。
- **WebGL2 当基线,WebGPU 只当增强**(微信 WebView 无 WebGPU、安卓碎片化、iOS 26 才有——押 WebGPU = 抛弃你最该服务的低端用户)。
- **引擎(若真上 3D):R3F(React-Three-Fiber)**,WebGL2 基线;drei+rapier+ecctrl 近乎白送一个第一人称走动控制器。拒 Babylon(~1.4MB、弱 React)、PlayCanvas(移动最强但编辑器中心、React 不友好)。
- **铁打的移动预算**:可见三角 <~3 万、draw call <~100、pixelRatio 锁 1–1.5、烘焙光(无实时光)、frameloop=demand、低端设备自动降级回 2.5D、锁 30fps。
- **国内分发修复(不管渲染怎么选都先要)**:自定义域名(**绝不用 \*.vercel.app**,GFW DNS 污染/SNI 封)、自托管引擎+全部 3D/视频资产到**免 ICP 的 HK/SG/JP 近源边缘**、停用 unpkg/jsdelivr(jsdelivr 已丢 ICP、被污染)。
- **真机 QA 环**:无头 preview 没 WebGL,**只能在真·1500–2500 元安卓 + 微信内置浏览器里测**。

## 资产路径(扁平立绘 → 3D 的真相)
仓库实锤:全部美术是**扁平单层 raster**(`oc/larus-canus/art.jpg` 等),**零 .glb/.gltf/.fbx**。
- **2.5D 立牌/西洋镜**:唯一能**原样复用**扁平立绘的路(Three.js Sprite 相机朝向 quad + 深度图视差,Paper Mario/DOOM/Don't Starve 技法),~图片级 GPU 成本。**推荐。**
- **全 3D**:唯一能给"真身体转身"的路,但每个角色都得**从零建模+绑定+卡通着色**(扁平立绘只是参考、不可复用):**~$2.5k–6k、60–120h/角色** + 单算的建模烘焙房间。团队没这条美术线。
- **AI 生 3D(Tripo/Meshy/Hunyuan3D/Rodin,2026)**:对风格化二次元只到**blockout 级,不可直接上**(都要重拓扑+绑定清理;自动绑定在异常比例上失败=正好是二次元)。`~60s game-ready` 是营销话。
- **诚实缺口**:2.5D 立牌"面向你"只是纸板转向相机;Live2D 本质是平面分层(头转 ~30–40°、上半身、**明确做不到 360°/真身体转身**)。**所以 2.5D 和 Live2D 都给不了"OC 整身在 3D 里转过来"**——那一个节拍才是唯一真 3D 触发点,且预渲染转身/单 hero 模型更划算。

## 选项
- **A. 2.5D + 预渲染(推荐 v1)**:低-中工程、**零 3D 建模**、复用现有扁平立绘 + libtv/niji7。代价:一条隔离 Vite 路由 + 预渲染图序列(分镜→AE)+ GLSL 转场 + 主角 Live2D 绑定(每角色一道美术活,~$300–1500/角色)。**拿到所有情绪节拍 + "OC 看着你/实时变化"(Live2D),官网"质感",WebGL2 在微信 WebView 低端安卓能跑,热风险低。~90% 效果 / <10% 自由漫游成本。**
- **B. 混合:小型烘焙 3D 房间 + 2.5D/Live2D 角色(可选 Phase2,仅当去险原型过)**:中-高;AI 生 3D blockout 房间 + 美术清理烘焙,角色仍 2.5D/Live2D,严格移动预算 + 低端自动降级。给到"走进并环视一个真 3D 书店"感,角色仍是转向相机的立牌。
- **C. 全自由漫游 3D + 全 3D 角色(不推荐)**:最高成本、最低信心;团队没有的建模美术线、AI 生 3D 到不了官网脸、分叉扁平 2D 管线、最可能把低端安卓热到掉帧;还**反噬"看 OC 实时变化"**(改 3D rig 比换 2D 层难得多)。唯一能给"随便走 + OC 真身体转身"。

## 先做的去险原型(花掉任何钱之前)
**一个一次性 spike:** 隔离 Vite 路由,渲一个**烘焙光小西洋镜房间**(单优化 GLB,烘焙贴图=运行时光免费)+ 现有扁平 OC 立绘当相机朝向立牌 + 深度图视差,单 canvas,可见才跑 frameloop,pixelRatio 1–1.5,屏上显示实时 draw call/fps。自托管到 HK/SG 自定义域(顺便验国内分发)。**在真·1500–2500 元安卓 + 微信内置浏览器里连续 soak 5–10 分钟**,门槛:draw call <~100–150、三角 <~3 万、稳 30fps **无热崩**、掉电/发热可接受、跨 GFW 初载可忍。过 → 才值得 scope Phase B;**不过 → 退回 2.5D/预渲染(引擎从来不是问题)**。花几天、用现有美术、零建模。

## 推荐
**v1 别做自由漫游 3D**——而且认清愿景里没东西需要它。**先上 Option A(2.5D + 预渲染)**:命中每个节拍、复用扁平立绘零建模、移动/热安全。**并行先修国内分发**(自定义域 + 自托管资产 + 免 ICP HK/SG/JP 边缘 + 停 unpkg/jsdelivr,它 gate 一切)。Live2D 只用在 1–2 个 hero 时刻(糖沐收银台、创作桌的 OC)。自由漫游 3D(B/C)当**以后、隔离、能力门控、自动降级**的路由,**且去险原型过 5–10 分钟真机热 soak 前不立项**。引擎若真上=R3F+WebGL2 基线。

## 唯一会翻盘的设计决定(你来定)
**如果你宣布"自由漫游体验本身(真的在空间里走 + OC 在 3D 里转身)就是产品非妥协卖点"**——不是它实现的任何功能,而是这个体验本身——那裁决才从"没元素需要"变成"体验需要",Option C 的全部成本/热/预期现实才打开。**这是设计决定,不是工程决定。**

## 关键提醒
- **热/电是真·绑定风险,与引擎无关**——选 R3F 不去险,只有 场景预算+2.5D 策略+真机 soak 才去险。
- **官网当标杆是陷阱**:终末地是 ~28GB 原生客户端(骁龙 8+ Gen1);官网那种"质感"也靠预渲染视频+2D 视差+on-rails WebGL,不是自由漫游。拿这个 bar 套 web-mobile-China 必爆预算。(注:终末地官网确有**受约束的实时 3D 模型查看器**——但是 orbit/rotate,不是自由漫游。)
- **数字软引用**:three.js 下载量被夸大、"3D=3.2x 电"未证实、"60fps 比 30fps 费电 40–60%"是原神特例、"60s game-ready"是营销——方向对、数值软,引用前别当硬事实。
- **rigging 长杆**:Live2D 和 "扁平→深度立牌" 都要先把单层图**拆层**(每角色一道活;AI 自动拆需人工修)。
- preview 无 WebGL,3D/2.5D 全得真机验;ICP 没有 = 国内只能用 HK/SG/JP 近源,有延迟。
